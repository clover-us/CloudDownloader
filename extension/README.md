# CloudDownloader 接力（浏览器扩展）

浏览器不会让外部程序接管它自己的下载，所以真正「点了链接、文件直接进 CloudDownloader」只能靠扩展：
本扩展监听浏览器创建的下载，先把地址和它携带的 Cookie / 来源页面 / 浏览器标识交给桌面端，
桌面端确认收下后才取消浏览器里那份，由 CloudDownloader 继续下载。

## 安装（开发者模式）

1. 打开 Chrome / Edge 的扩展页：`chrome://extensions` 或 `edge://extensions`。
2. 打开「开发者模式」，点「加载已解压的扩展程序」，选择仓库里的 `extension/` 目录。
3. 打开扩展的「选项」，点「测试连接」确认显示「已连接」（需先启动 CloudDownloader）。
4. Chrome 可能提示扩展可以读取浏览记录和 Cookie，这是它把登录状态转交给下载器的前提。

## 行为

- 只接管 `http(s)` 直链；`blob:`、`data:` 这类浏览器内部地址没有可供外部下载的 URL，会被跳过。
- 桌面端没开、端口不对或请求被拒绝时，浏览器会照常下载，不会两头落空。
- 默认接管所有站点。可以在选项里填站点白名单（每行一个域名，自动包含子域名），
  例如 `example.com`，普通网页下载就继续交给浏览器。
- 也可以设置体积下限：小于该体积的文件留给浏览器。
- 在链接上右键有「用 CloudDownloader 下载」，用于不想自动接管时手动发送。

## 安全边界

- 扩展只连 `http://127.0.0.1:17890`（端口可在选项里改），不会发出本机。
- 桌面端只接受 `Origin` 是 `chrome-extension://<扩展 ID>` 的请求；网页无法伪造这个头，
  跨站请求也会先被浏览器的 CORS / Private Network Access 拦下。
- Cookie 只在一次接力里传给本机进程，用于随后的下载请求；桌面端不写日志，也不落盘。
- 桌面端对链接只接受 `http`、`https`、`magnet`，且拒绝控制字符和超长内容。

## 已知限制

- 需要登录但用一次性签名 URL 的站点，签名过期后从桌面端重试会失败；重新在浏览器里点一次即可。
- 受 DRM / 分片加密保护的视频没有可供外部下载的直链，本扩展不会也不能绕过。
- 扩展未上架商店，需要以「加载已解压」方式安装；升级时替换目录后点一次「重新加载」。
